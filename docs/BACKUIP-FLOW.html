Overview: who does what

The web service never runs as root and never touches site files. It only writes settings and asks the helper to start a job. A root systemd unit does the work and drops result files that the service reads back.

Web service (servanago)

Backups page, settings, passphrase and ntfy URL sealed in SQLite, run history, audit log, banner, one-use download links.

Helper (root socket)

Typed actions backup-enable, backup-start, backup-restore, backup-status. Installs units, writes request.json, starts the unit.

Job (servanago-backup.service)

servanago backup-job run as root. Reads a snapshot of the panel DB, builds archives, prunes, writes result files, sends ntfy.

Backup folder

<dir>/<scope>/<scope>-<time>.tar.zst.age plus a .json sidecar, and <dir>/.runs/ result files.
